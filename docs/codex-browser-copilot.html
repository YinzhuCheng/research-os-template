Research OS v3.4 Browser Copilot Bridge

This page defines how the Codex in-app browser becomes a research cockpit without pretending that browser JavaScript can execute research work by itself. The browser collects material, Codex performs analysis and execution after confirmation.

Material-first Flow

The fixed five-question intake is removed. The first screen only accepts text and material uploads. Codex then moves through pending_intake_analysis and creates three targeted questions based on the material.

Browser-to-Codex Bridge

Browser responsibility

PUBLIC/copilot.html collects text, source links, and files. When the local bridge runs, it posts to /api/intake. Without the bridge, it can export a local draft JSON packet.

Bridge responsibility

The plugin server writes sanitized packets to CONTROL/copilot_inbox/, private raw uploads to runtime-only intake storage, and public progress to PUBLIC/copilot_state.json.

Codex responsibility

Codex reads pending packets through the research-os-copilot skill and asks for confirmation before analysis, initialization, execution, public export, or resource use.

Sync back to browser

Codex writes sanitized state and repository links. The browser renders Overview, Literature, Theory, Experiment, and Repository Links from that state.

Local Runtime

The browser cockpit can render statically, but the bridge workflow needs the local runtime described in docs/environment.md. Use the checker before starting the bridge.

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check_environment.ps1 -RequireCodexPluginFiles
python .agents/plugins/plugins/research-os-copilot/scripts/research_os_copilot_server.py --serve

Initialization Report Requirements

After the researcher answers the three questions, Codex initializes a startup package, not a final paper. The default report must include motivation, expected goals, contribution claims, related work shortcomings, reference links, and repository resource links.

Theory-heavy projects

Render a theory framework, key definitions, candidate theorems, and proof or validation notes. Mathematical proof work remains non-formal by default and should preserve conjectures, examples, counterexample searches, and proof gaps.

Experiment-heavy projects

Render an experiment plan, metrics, stopping rules, and minimum validation. Concrete spending is blocked until the researcher supplies a budget.

Safety Boundaries

The browser never bypasses Research OS governance. It cannot authorize paid resources, external writeback, public export, or submission. It only creates structured packets and state for Codex to review.
  • Raw uploads are runtime-private and must not enter PUBLIC/, docs/, or git-tracked provenance.
  • Reference downloading uses download_reference_links.ps1 and only attempts open URLs or landing pages.
  • Zip files are stored as material. They are not automatically executed or unpacked into the project.
  • Chat links are recorded first; fetching requires explicit authorization.
