Start Research OS From Material

You do not need to answer a long setup questionnaire. Open the copilot page, describe the direction or upload material, then Codex asks only three targeted questions before initialization. After that, Research OS runs as a three-phase system: initialization, semi-automated loop research, and final product.

First Step

Open the cockpit

Use PUBLIC/copilot.html as the first screen.

Add material

Upload a research plan, notes, ChatGPT conversation export, PDF, zip, or demo. A short text direction is also enough.

Let Codex profile it

Codex classifies the project as theory, experiment, theory+experiment, engineering system, survey, or unclear.

Check The Local Environment

Before the first run, read docs/environment.md and run the environment checker. Install commands may need small changes by operating system version, enterprise image, proxy, or package manager.

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install_environment.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check_environment.ps1

The Three User-Facing Phases

1. Initialization

Material intake, exactly three targeted questions, privacy boundaries, initial plan, and startup package.

2. Semi-Automated Loop Research

Each loop starts with researcher acceptance of the previous artifact, then plan alignment, user decision, execution, and analysis.

3. Final Product

Select paper, research report, software, or multiple tracks. Export, release, and submission still require a separate human gate.

The UI uses these macro phases. The internal Research OS state machine still keeps work orders, phase gates, resource guard, manifest, ledger, privacy scan, candidate/evaluator objects, and export gates.

Only Three Targeted Questions

Questions are generated from the material. Each has a recommended answer, options, and an Other/free-form answer path.

What Initialization Produces

  • Research motivation and expected goals.
  • Contribution claims.
  • Related research, shortcomings, and how this research relates to it.
  • Reference links and a lawful download script.
  • Theory framework and candidate theorems when the project is theory-heavy.
  • Experiment plan and minimum validation when the project has experiments.
  • Repository links to work order, phase gate, schemas, templates, manifest, and ledger.

How The Research Loop Works

  1. Review the current artifact and accept it, or give revision instructions.
  2. If it is accepted, Codex proposes the next action plan and 1-3 high-impact alignment questions.
  3. Choose a recommended/default option or answer in natural language.
  4. Codex executes inside the approved work order and records audit artifacts.

If you do not accept the current artifact, the system stays in revision mode and must not move to the next step.

Final Product Choices

Paper

Use when a target venue, template, comparable papers, LaTeX/PDF output, and review/rebuttal iteration matter.

Research Report

Use when the research process, initial data, negative results, and reproducibility details matter more than venue novelty constraints.

Software

Use when practical utility and user experience matter. The default target is stable, engineered, polished, and documented software.

Every final-product selection includes default options and a natural-language field for venue, format, audience, quality expectations, or constraints.

Git-Backed Archives

Use the archive dialog before long pauses, risky transitions, or final-product work. Each archive records timestamp, current phase, git commit, and your description. The public index is sanitized at PUBLIC/archive_index.json; private material and secrets are forbidden.
