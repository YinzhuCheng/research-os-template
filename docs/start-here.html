Human-in-loop Auto Researcher

把一个研究想法变成可执行、可追踪、可审计的研究仓库

Research OS 不要求你先懂 Codex、LLM、机器学习或论文流程。你只需要给出研究目标、材料边界和资源约束，仓库会把后续工作拆成阶段闸门、skill、模板、证据链、资源账本和公开产物。

开始三步 选择领域模式 查看研究内核 查看技术路线 浏览模板

研究内核：先列出计算

v3.2 把所有领域流程统一成 `generate -> evaluate -> update -> human gate`。任何候选想法、模型、算法、实验方案或 estimand 都先进入 research-os-research-kernel，再调用领域 skill。

Candidate

当前要研究的对象：猜想、模型、方法、算法、系统、estimand、设计或协议。

Evaluator

必须列出 metric/check、formula/procedure、inputs、scale、threshold、resource、failure mode 和 replay。

Trace

失败、反例、不稳定、leakage、诊断失败和不确定结果必须进入 `negative_result` 或 `search_trace`。

三步开始

Step 1

写下研究入口

把研究问题、已有材料、隐私边界和你愿意投入的资源写进入口材料。还不确定的内容保持空白，不要让 agent 替你默认模型、数据集、样本量或预算。

查看决策记录模板
Step 2

确认控制面

检查当前 work order、phase gate 和项目配置。真实资源、凭据、外部写回、公开导出和投稿默认都需要人工确认。

打开 work order
Step 3

运行最小可行性探针

先做最小验证，再扩大实验或写作范围。每次实质运行都要记录 manifest 和资源 ledger。

查看 feasibility 模板

你需要回答什么

Research OS 会尽量从仓库里发现事实，但研究意图和资源边界必须由人确认。

  • 研究目标：这次要得到研究简报、验证报告、复现包、决策备忘，还是论文草稿？
  • 材料边界：哪些材料可公开，哪些只能放在 `PRIVATE/`，哪些不能落盘？
  • 预算边界：允许多少时间、算力、云资源、API、人工或仪器机时？
  • 停止条件：什么情况下必须停下来问人，例如证据冲突、预算超限、许可证不清楚或实验失败？

需要领域口味时

如果研究已经明显属于基础数学、应用数学、机器学习、计算机科学或统计学，可以先进入 领域模式。领域模式不会替代控制面；它只是在 work order、phase gate、manifest、ledger 和隐私扫描之上，加载对应学科的产物模板、agent roles 和质量闸门。

基础数学

猜想、例子、反例、证明策略和 proof-gap review。

机器学习

任务卡、数据许可、baseline、ablation、leakage audit 和复现。

统计学

estimand、识别假设、诊断、不确定性和敏感性分析。

最小命令

Windows PowerShell 环境中可以先运行这些只读或校验命令。

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate_schemas.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check_harness.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check_research_kernel.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\scan_privacy.ps1
关键边界：不要把真实 API key、平台 token、cookie、authorization header、SSH 私钥或云账号密码写进仓库。需要凭据时，只记录环境变量名或 secret store 路径。
