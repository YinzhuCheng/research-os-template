系统架构

数据流和审计流

输入对象

研究入口被拆成 `research_project`、`work_order`、`phase_gate`、`feasibility_probe`、`resource_budget` 和 claim-evidence。入口不足时只生成对齐问题，不补默认模型或数据集。

查看项目配置

运行对象

每次实质运行都写入 `run_manifest.jsonl`，真实或计划资源进入 `resource_ledger.jsonl`。失败状态也要记录，避免后续 agent 把 partial run 当成成功结果。

查看 run manifest

证据对象

时效性信息进入 `live_evidence_snapshot.yaml`，面向公开产物的主张进入 `PUBLIC/claim_evidence_matrix.yaml`。无法联网时必须标注高 freshness risk。

查看 live evidence

公开对象

`PUBLIC/` 只放可公开或已脱敏内容。公开导出前运行隐私扫描，私有原始材料和敏感审计留在 `PRIVATE/`。

Harness engineering

路径和权限

`CONTROL/work_order.yaml` 定义 allowed paths 和 forbidden paths。默认禁止写入 `PRIVATE/`，真实外部资源和公开导出要人工确认。

Codex 控制面

`AGENTS.md` 写长期仓库规则；`.codex/config.toml.example` 和 hooks 示例说明 sandbox、approval、PreToolUse、PostToolUse 和 Stop 检查策略。

资源守护

`research-os-resource-guard` 和 `check_resource_guard.ps1` 管理预算、ledger、阈值和人工确认。云平台硬上限仍需在云侧设置。

验证闭环

新增检查覆盖 HTML 链接、skill 镜像、integration registry 和 harness run schema，防止文档和执行入口脱节。

开源自动研究组件适配

v3 采用积极集成策略，但默认不复制大段第三方源码。每个组件以 registry 记录来源、许可证、安装方式、需要的环境变量名、适合的 Research OS 阶段、产物映射和风险。
