Research OS v3.4 Technical Report

Research OS is a structured human-in-loop auto researcher. v3.4 makes the runtime environment explicit, prunes stale generated outputs, and keeps the material-first browser cockpit, research kernel, domain profiles, work orders, phase gates, manifests, ledgers, and privacy boundaries connected.

Architecture

Runtime Environment

The repository has a documented environment contract. Required tools are Git, PowerShell, Python 3.10+, a modern browser, and the Codex desktop app for the full in-app browser workflow. LaTeX and Node.js remain optional.

Material-first Copilot

The first screen no longer asks five fixed questions. It accepts free text or uploaded material and recommends uploading drafts, chats, PDFs, zips, or demos. Codex routes the packet through research-os-orchestrator, then generates exactly three targeted questions before initialization.

Research Kernel

All substantive work must pass through research-os-research-kernel. This prevents the repository from becoming a toolbox of unrelated prompts.

candidate
-> evaluator_contract
-> evaluation_result
-> belief_state
-> search_trace / negative_result
-> next_action_policy
-> human_judgment_gate

Evaluator contracts must list metric or check, procedure, inputs, scale, acceptance threshold, resource estimate, failure mode, and replay note.

Domain Modes

Fundamental Mathematics

Definitions, examples, conjectures, counterexample search, lemma decomposition, proof strategy, proof-gap review.

Applied Mathematics

Model assumptions, scaling, stability, error, numerical validation, sensitivity, interpretation limits.

Machine Learning

Task cards, data license, baselines, ablations, leakage audit, reproducibility, cost-performance.

Computer Science

Problem specs, invariants, complexity, system design, benchmarks, artifact evaluation, threat models.

Statistics

Estimands, identification, sampling and power, diagnostics, uncertainty, causal diagrams, sensitivity.

See domain-modes.html and domain_profiles/README.md.

Harness Engineering

The browser can enqueue material; it cannot authorize execution. Codex still follows work orders, phase gates, path boundaries, manifests, ledgers, privacy scan, and budget confirmation.
  • Raw uploads are runtime-private and excluded from git.
  • Reference downloads use open-access or landing-page attempts only.
  • Experiments require a researcher-provided budget before minimum validation.
  • External writeback, public export, and submission require confirmation.
