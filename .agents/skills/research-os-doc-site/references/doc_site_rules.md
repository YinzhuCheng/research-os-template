# Documentation Rules

- `docs/desktop-app.md` should answer what the app is, how `.rosproj` projects work, and where the researcher starts.
- `docs/architecture.md` should answer how the app is wired, what state files matter, how skills route work, how integrations map outputs, and how validation is run.
- Durable docs should link through repository-relative paths and appear in `docs/doc_map.yaml`.
- `PUBLIC/dashboard_data.json` is sanitized app data, not a static dashboard page.
- Do not reintroduce static HTML documentation as a primary surface.
